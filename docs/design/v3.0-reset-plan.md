## 2. 事实基线

> 以下数据为 2026-11-13 在 `main`（测量时 HEAD **`eba9341`**）的实测值。它们描述 2.x 资产与风险，不作为 3.0 继续沿用 macOS-only 技术决策的理由。
>
> ⚠️ **这是一份冻结快照，不是「当前值」。** 除「本机运行时观测值」（如 UserDefaults plist 体积，见 §2.2）外，全部数字只对 `eba9341` 成立，后续 commit 会让它们漂移。复核方式：`git ls-tree -r --name-only eba9341` 枚举文件后逐个 `git show eba9341:<path> | wc -l`。旧版本曾把基线标成 `aa549ce`，但那组数字逐项匹配的是 `eba9341`（`aa549ce` 上生产代码是 36,976 行 / 测试 45,989 行 / `AppDelegate` 1,866 行），而「提交数 1,365」又恰好是 `aa549ce` 的值 —— 旧版本身是跨 commit 混采的，已按实测统一到 `eba9341`。

### 2.1 代码与测试资产

| 项 | 实测 | 3.0 的处理方式 |
|---|---:|---|
| 生产代码 | 36,998 行 / 114 个 `.swift` 文件 | 不逐行翻译；按行为域重建 |
| 测试代码 | 46,174 行 / 155 个 `.swift` 文件 | 提炼行为矩阵、黄金样本和故障注入用例 |
| 测试数量 | 1,483 | 不设“新语言测试数不得下降”门；要求行为覆盖不下降 |
| 提交数 | 1,366 | 保留缺陷知识与决策可追溯性 |

### 2.2 2.x 的结构性问题

| 问题 | 实测 | 3.0 必须消除的根因 |
|---|---|---|
| 存储写放大 | 历史、回收站、标签挤在约 370 KB 的 UserDefaults plist（**本机运行时观测值**，不在仓库内，无法由 commit 复现） | 改为增量 SQLite；写入成本不得随全库条数增长 |
| SQLite 尚未成为主库 | 5,135 行相关代码处于已验证副本/镜像阶段（口径 = `SQLiteSchema` 372 + `SQLiteSchemaMigrator` 505 + `SQLiteStorageBackend` 1,250 + `SQLiteBinder` 92 + `SQLiteRowDecoders` 257 + `StoreMigration` 410 + `StorageMirrorService` 442 + `TrashStore` 950 + `StorageBackend` 857，9 个文件在 `eba9341` 上逐个可复算） | 移植不变量，不把镜像代码误当跨平台核心 |
| 上帝对象 | `ClipboardStore` 3,030 行；`AppDelegate` 1,888 行 | 领域、存储、平台、UI 分层，禁止 UI 直访数据库 |
| 并发不可证 | 22 个 `nonisolated(unsafe)`、33 个 `NSLock()`、125 处 `DispatchQueue` | 单写者、明确事件边界、可取消任务、受审计的 `unsafe` |
| UI 状态膨胀 | `ContentView` 1,139 行、30+ `@State`、5 组手工缓存 | Feature 状态单一所有者，列表由查询结果驱动 |
| 平台耦合 | 纯 Swift / SwiftUI / AppKit / Keychain / Sparkle | 领域核心不依赖任何 OS UI 或系统密钥 API |

### 2.3 必须保留的兼容性资产

| 资产 | 3.0 约束 |
|---|---|
| 加密格式 v2 + v1 legacy 读取 | 作为**跨语言数据契约**保留；用黄金密文验证，不要求沿用 Swift 实现 |
| `.clipmemory` 备份包 | 3.0 必须能导入；必须提供 v2 可读的回滚导出能力 |
| Keychain 根密钥与现有 macOS 数据 | 迁移时只读使用；原密钥与原数据不得被迁移过程覆盖 |
| 测试隔离思想 | 所有存储、时钟、剪贴板、系统密钥和更新源必须可替换，测试不得污染真实用户数据 |
| 7 语种翻译资产 | 复用语义与译文；允许更换为跨平台本地化机制，但运行时切语言与复数能力不得回退 |
| 历史 ledger | 归档保留，不重写历史结论 |

## 3. 重置边界

### 3.1 重建区

| 层 | 3.0 目标 |
|---|---|
| 领域核心 | 条目、标签、回收站、Snippets、搜索、保留策略、去重与敏感内容规则跨平台共享 |
| 存储与迁移 | 新 SQLite 主库；v2 数据只读导入；增量事务写入；崩溃后收敛 |
| 平台适配 | 剪贴板、热键、回贴、密钥库、窗口/托盘、自启动、更新按系统实现 |
| UI 壳 | QuickBar、主窗口、设置三入口；共享设计令牌，平台行为各自遵循系统惯例 |
| 本地化 | 独立于 UI 工具包，支持 7 语种、运行时切换、复数与占位符校验 |
| 发布 | 三平台签名、安装、更新与回滚分别验证，不把 Sparkle 当跨平台方案 |

### 3.2 不重建为“全新产品”的部分

- 本地优先、真加密、无使用统计的定位不变。
- QuickBar 快速入口、主窗口管理入口、菜单栏/托盘入口的分工不变。
- 回收站、条件删除、诊断横幅、排除应用、加密备份等用户痛点能力不得无声消失。
- 2.x 在 3.0 开发期只接受安全、数据完整性和严重回归修复，不并行增加大功能。

### 3.3 明确不做

- 不在同一阶段同时更换核心、UI 技术并加入云同步。
- 不做逐文件、逐 API 的 Swift → Rust 机械翻译。
- 不在 3.0 引入插件市场、通用脚本引擎、云端 AI 或跨设备同步。
- 不为了“统一”而把 macOS 的 Liquid Glass、Windows 的 Fluent 或 Linux 桌面组件机械复制到其他系统。
- 不在 3.0 自动删除 v2 数据库、plist、图片目录或密钥。

## 4. 决策 D2：跨平台核心底座

### 4.1 目标架构

```text
┌──────────────────────────────────────────────┐
│ UI：Tauri 2 或 Slint（阶段 1 选定）           │
│ QuickBar / Main Window / Settings / Tray     │
└───────────────────┬──────────────────────────┘
                    │ commands / events / snapshots
┌───────────────────▼──────────────────────────┐
│ Rust Core                                    │
│ domain / search / snippets / retention       │
│ storage / crypto / backup / v2 migration     │
└───────────────────┬──────────────────────────┘
                    │ capability traits
┌───────────────────▼──────────────────────────┐
│ Platform Adapters                            │
│ macOS / Windows / Linux                      │
│ clipboard / hotkey / paste / key store / OCR │
└──────────────────────────────────────────────┘
```

逻辑目录目标如下；**本文件不要求一次性移动现有源码**：

```text
core/                   Rust workspace，无 UI、无 OS API
  domain/               条目、标签、回收站、Snippets、保留策略
  storage/              SQLite、事务、查询、schema 版本
  crypto/               加密格式、密钥使用、备份包
  migration/            v2 plist / SQLite 副本 / 备份包只读导入
platform/
  macos/                NSPasteboard、Keychain、Vision、Sparkle 桥接
  windows/              Clipboard、DPAPI、热键、回贴、更新
  linux/                X11、Wayland、Secret Service、桌面集成
apps/
  desktop/              阶段 1 选定的 UI 壳
fixtures/               跨语言黄金样本、损坏样本、性能语料
localization/           7 语种消息与复数资源
design/                 设计令牌与 UI 验收基线
```

### 4.2 核心规则

1. `core` 不 import 任何 UI 工具包，也不直接调用 Keychain、DPAPI、Secret Service 或系统剪贴板。
2. UI 只通过 command/query 获取不可变快照，不直接执行 SQL，不持有数据库锁。
3. 所有写操作进入**单写者串行命令流**；读取使用一致快照；锁定、退出和窗口关闭必须取消或排空相应任务。
4. 剪贴板回调只产生事件，不在 OS 回调线程中解密、搜索或写库。
5. 剪贴板条目保留原始表示与元数据；跨平台内部模型不得把富文本、HTML、图片或文件静默压成纯文本。
6. `unsafe` 目标为 0；确需使用时必须有隔离契约、审计记录和针对性测试。
7. 异步运行时、SQLite 绑定和具体 crate 在原型阶段确定并锁定版本，不以“最新”替代适配性验证。

### 4.3 加密与搜索边界

- macOS 使用 Keychain，Windows 使用 DPAPI，Linux 使用 Secret Service 保存或保护根密钥。
- Linux 无可用 Secret Service 时，**不得静默退化为明文密钥文件**；只能使用明确的密码解锁流程，或在支持矩阵中声明该环境不受支持。
- 数据库、日志、临时文件、崩溃报告和持久化搜索索引默认不得出现条目明文。
- 3.0 默认在解锁后建立内存搜索索引，锁定即销毁；若未来需要明文 FTS5 落盘，必须另做隐私设计评审，不得作为性能优化直接加入。
- OCR 默认设备端处理；任何云端 OCR 都不属于 3.0。

## 5. 决策 D3：UI 与平台能力选型

### 5.1 最大风险不是 UI，而是 OS 能力

三平台必须先验证以下能力，再讨论视觉完成度：

| 能力 | 必须回答的问题 |
|---|---|
| 剪贴板监听 | 文本、富文本、HTML、图片、文件如何表示？是否需要轮询？锁屏/休眠后如何恢复？ |
| 全局热键 | 权限、冲突、重绑定、IME 状态下是否可靠？ |
| 自动回贴 | 能否把内容写回剪贴板并粘贴到先前应用？无权限时如何可见地降级？ |
| 焦点与窗口 | QuickBar 是否能在当前显示器/空间正确弹出并恢复先前焦点？ |
| 系统密钥 | 锁屏、注销、密钥库不可用和权限撤销时如何失败关闭？ |
| Linux 桌面 | X11、Wayland、GNOME/KDE、托盘协议分别支持到哪一级？ |
| 无障碍与输入 | 键盘全流程、屏幕阅读器、中文/日文输入法、动态字体是否可用？ |

**Wayland 不得用 X11 的成功结果代替。** 若系统自动回贴或全局监听在特定 Wayland 环境无法可靠实现，产品必须明确降级为“复制到剪贴板”，而不是假装支持。

### 5.2 Tauri 2 / Slint 同链路原型竞赛

两个候选必须复用同一个 Rust core、同一份 10K 条测试语料、同一套设计稿，完成：

```text
复制文本/图片 → 加密保存 → 搜索 → 全局唤起 QuickBar
→ 键盘选择 → 回贴或明确降级 → 应用锁定
```

| 候选 | 验证重点 | 不能仅凭什么入选 |
|---|---|---|
| Tauri 2 | 三系统 WebView 差异、常驻内存、CSP/IPC 最小权限、UI 自动化、IME、焦点行为 | 安装包小、生态热门、页面开发快 |
| Slint | 长列表、无障碍、IME、屏幕阅读器、原生窗口/托盘集成、设计还原能力 | Rust 单语言、理论资源占用低 |
| 原生三壳（后备） | SwiftUI / WinUI / Linux 原生壳与 core 的绑定成本 | “原生一定更好”的直觉 |

若使用 Tauri：不得加载远程内容，不得开放通用 IPC，不得加入第三方统计脚本；CSP 与命令 allowlist 是发布硬门。

### 5.3 UI 硬门与决策方式

以下任一项失败，该候选直接出局，不用平均分抵消：

- 三平台目标环境完成同链路；降级行为符合支持矩阵。
- 10K 条列表可虚拟化滚动，搜索和键盘选择无明显阻塞。
- 中文/日文 IME、全键盘操作、屏幕阅读器基础路径可用。
- 能建立可重复的 UI 自动化与视觉回归基线。
- 锁定后无明文渲染、无敏感计数泄露。
- 可承载 7 语种、动态字体、深浅色和减少动态效果设置。

通过硬门后，再比较：常驻内存、空闲 CPU、冷启动、列表帧时间、安装包体积、开发/测试成本。最终产出选型 ADR 和并排样稿，**经确认后才进入生产 UI 开发**。

## 6. 决策 D4：存储与迁移策略

### 6.1 不再沿用旧的 2.x 切换主线

原草案中的 `PR-C → PR-C-switch → PR-E` 是 macOS-only 前提下的 SQLite 切换计划，不再作为 3.0 主线：

- 3.0 不要求先把 2.x 的 UserDefaults 主库切换成 Swift SQLite。
- 3.0 不执行 PR-E，不删除旧 blob。
- 既有 Swift SQLite schema、迁移、镜像与变异测试继续作为**行为规格和故障样本来源**。

### 6.2 v3 独立建库，v2 只读导入

```text
v2 原始数据 ──只读快照──> v3 migration adapter ──事务导入──> v3 新数据库
      │                                                        │
      └── 原文件、原密钥、原图片不修改                         └── 失败可整库重来
```

| 规则 | 要求 |
|---|---|
| 数据隔离 | alpha/beta 使用独立应用身份与数据目录；只有显式迁移向导可只读访问真实 v2 数据 |
| 权威来源 | 当前 2.x 以 UserDefaults 为权威来源；SQLite 镜像用于交叉校验。若未来权威来源改变，新增版本化 importer |
| 导入一致性 | 文本 hash、图片 hash、标签、置顶、回收站、时间戳逐项对账 |
| 失败策略 | 导入失败不覆盖 v2，不把部分导入标记为成功；可诊断、可重试 |
| 并发运行 | 迁移与日常使用不得让 v2/v3 同时静默捕获；提供明确单实例/冲突提示 |
| 回滚 | 保留 v2 原数据；v3 提供 v2 可读的备份导出，回滚演练必须覆盖 v3 新增历史 |
| 删除 | 3.0 不自动清理 v2 数据；任何删除都只能由用户在迁移成功后显式执行 |

## 7. 阶段划分与验收门

> 每阶段必须独立可演示、可回滚。不是每个原型阶段都向用户发布，更不是所有阶段都打进同一个大爆炸版本。

### 阶段 0 · 事实基线与三平台能力验证

**范围**

- 保留原方案的 macOS 真机/VM 冒烟：热键、焦点、菜单栏、更新、权限、IME、辅助功能、锁屏唤醒、多显示器、深色模式。
- 在 macOS、Windows、Linux 建立最薄 OS adapter 原型。
- Linux 至少区分 X11 与 Wayland，记录桌面环境和窗口系统，不写“Linux 已支持”的笼统结论。
- 采集 2.x 性能基线和参考硬件信息：启动、常驻内存、空闲 CPU、10K 保存/搜索、安装包体积。

**不做**：不改生产存储，不迁 UI，不导入真实用户数据。

| 门 | 判据 |
|---|---|
| G0-1 | macOS 现有 10 项冒烟逐项留截图/日志；失败项先修或登记为明确迁移约束 |
| G0-2 | 三平台均完成文本与图片的捕获、写回剪贴板；原始表示差异有清单 |
| G0-3 | 三平台均验证全局热键、先前焦点恢复、回贴；不能回贴的环境展示可见的 copy-only 降级 |
| G0-4 | Keychain / DPAPI / Secret Service 的锁定、解锁、不可用和权限撤销路径均有结果 |

## 9. 竞品 REA 与功能转化

> REA 在本方案中指 **Reproduce → Explain → Abstract** 的功能级逆向分析。只使用公开版本、公开文档和许可允许的源码；不绕过付费/保护机制，不复制视觉资产，不直接搬运不兼容许可证的代码。

### 9.1 统一拆解模板

每个竞品功能必须记录：

1. **Reproduce**：入口、前置条件、操作步骤、可见结果、异常与边界。
2. **Explain**：状态机、数据模型、OS API 边界、性能成本、隐私风险；公开源码只用于验证推断。
3. **Abstract**：提炼与具体 UI/代码无关的规则，给出 ClipMemory 最小实现、测试用例和不做的部分。

### 9.2 首轮对象与转化边界

| 对象 | 重点功能 | 3.0 吸收 | 3.0 不吸收 |
|---|---|---|---|
| Maccy | 轻量弹窗、键盘优先、短操作链 | QuickBar 作为最高优先级入口，以唤起到回贴耗时验收 | 为追求极简而删掉回收站、加密和诊断 |
| CopyQ | 标签页、直接粘贴、规则/命令 | 收藏板、顺序粘贴、少量内置文本动作 | 通用脚本引擎与任意命令执行 |
| Paste | Pinboards、预览、内容组织 | Snippets / 收藏板，与现有置顶合并语义 | 3.0 云同步、重资源视觉浏览 |

### 9.3 范围优先级

| 优先级 | 内容 |
|---|---|
| P0 | 数据兼容、三平台捕获/搜索/回贴、暂停捕获、应用锁、回收站、备份、7 语种 |
| P1 | Snippets、顺序粘贴、内置文本动作 |
| P2 / 非 3.0 | 云同步、插件、通用脚本、云端 AI、社交或团队协作 |

任何 P1 影响 P0 的性能、数据或发布门时，先砍 P1，不放宽 P0。
