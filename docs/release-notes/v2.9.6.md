# 剪忆 ClipMemory v2.9.6 — 回收站不再静默丢数据 / The Trash no longer loses data silently

**发布日期 / Release Date**: 2026-10-24
**类型 / Type**: Minor release
**本次改动规模**: 185 个提交（75 修复 / 26 重构 / 16 测试 / 9 新特性 / 7 CI / 52 文档·样式·杂项），覆盖 ID-CRASH-0022·0031·0032·0035·0038·0057–0066、ID-REVIEW-1001–1022·1024·1025、ID-FLAKE-0001–0008、ID-REL-1–3、ID-CI-0022、ID-BACKUP-0006

## 中文

### 主要更新 (Highlights)

- **🗑️ 大批量清理回收站前先问你** — 一次性要删 ≥20 条过期条目时不再直接动手：菜单栏图标亮起红色数字角标，点它才弹确认框（永久删除 / 取消）；低于阈值的小额清理保持静默。保留期从此不再是硬上限——数据安全优先于保留语义。（ID-CRASH-0035）
- **🛡️ 回收站与剪贴板历史不再静默丢数据** — 回收站读入失败不再被空数组覆盖（以前会把你的回收站整个抹掉）；回收站的删除对你可见，不再只写进 log；剪贴板写入失败会重试且状态可观测。两个剪忆同时开着也不会互相覆盖——第二个实例启动即退，一个字节都不碰。（ID-CRASH-0022 / 0032）
- **🛡️ 备份漏写隔离副本现在会告诉你** — 隔离副本写入失败以前会让**整份每日备份一起作废**（备份目录被删掉）；现在失败被单独记下来，备份本身照常完成，并在「设置 → 备份」页显示红色提示。隔离副本本身也被带进每日备份和导出包（ID-BACKUP-0006），跨磁盘卷的 Images/ 硬链接降级为拷贝，而不是让整次每日备份失败（ID-REVIEW-1018）。
- **🔐 `sk-` 服务令牌重新被识别** — 厂商前缀型密钥（`sk-ant-…`、`sk-or-…`）的尾部带连字符，上一版规则会在第一个连字符处停住而漏判；现在能识别，同时不会再误伤 `task-` / `risk-` 这类普通带连字符的词。（ID-REVIEW-1024）
- **⚙️ 新的 SQLite 存储层已就位，但尚未启用** — 真实的 SQLite 后端、schema 版本权威化、原子迁移与回收站独立维度都已完成（ID-REVIEW-1024，共 23 个提交，本版最大工程量）。**你的数据仍在原来的本地文件后端里，加密格式和存储位置都没有变化**；这一层是为将来接线做好的预备件，接线前还有几处硬前置条件要补齐（见 `docs/design/storage-migration.md` §4.4.1 / §5.5）。

### 修复 (Fixes)

**数据安全**

- **🛡️ 清理回收站先落盘再删图片文件**（ID-REVIEW-1024）— 以前先删文件再记账，中途崩溃就再也对不上账；现在先持久化再删，写失败时弹窗告警。
- **🛡️ 隔离副本被拒绝恢复时不再误报「备份包损坏」**（ID-REVIEW-1024）— 恢复包本身没坏，拒绝原因改用专门的文案。
- **🛡️ 密钥链临时不可用不再报「加密失败、条目未保存」**（ID-REVIEW-1024）— 这种情况其实什么都没丢（密钥没被重建、没有覆盖），现在明确说「正在重试，已有数据未受影响」。
- **🛡️ 测试进程再也不可能碰到你的真实数据**（ID-CRASH-0031）— 判定「是否生产环境」改用 domain 而不是实例身份，同时修掉永久错误导致的重试死循环与隔离路径缺口。
- **🛡️ 大批量清理的「已问过」标记改成按条目集合记，不再按条数**（ID-REVIEW-1025）— 以前同样 20 条的两次清理会被当成同一批，第二次悄悄跳过：回收站只涨不删，也没有任何提示。
- **🛡️ 已经问过你的那批数据，在你回答之前不会被自动删掉**（ID-REVIEW-1025）— 以前你恢复了几条之后，剩下的条数掉到阈值以下，就被当成「日常清理」直接删了，问过等于没问。
- **🛡️ 点「取消」不会再把 Quick Bar 锁死**（ID-REVIEW-1025）— 以前取消后角标一直在，之后每次点菜单栏图标都弹同一个确认框，Quick Bar 打不开，只能重启 App。现在取消＝稍后再问：角标撤掉，条目不删，下一轮再问一次。
- **🛡️ 待处理状态结束时会通知界面**（ID-REVIEW-1025）— 以前你自己把那些条目恢复或删掉后，角标还挂着，Quick Bar 一直打不开。现在状态一变就通知界面，角标立刻撤掉。
- **🛡️ 永久删除回收站条目时不再复活别的条目**（ID-REVIEW-1025）— 删除前先把内存里的最新状态落盘，避免用旧数据覆盖；以前刚恢复的条目会重新出现在回收站里（同时还在历史里）。

**备份与恢复**

- **⚙️ 导出清单的判定改成「字段缺失」而不是「字节相同」**（ID-REVIEW-1024），并从重新加密后的实际载荷计数，而不是源数据。
- **⚙️ v3 导出的包密钥一次性封缄**（ID-REVIEW-1015）— 导出包的密钥用完即焚。
- **⚙️ 自动备份的错误消息在日期之前记录**（ID-REVIEW-1024）— 以前日志里的日期对不上。
- **⚙️ 备份之间改用硬链接，并显示真实磁盘占用**（ID-REVIEW-1018）— 备份目录体积不再按份数虚高。
- **⚙️ 隔离副本已经恢复后，红色提示不再一直挂着**（ID-REVIEW-1025）— 以前旧记录不会自己消失，失败条数的分母也偏大。

**敏感内容检测**

- **🔐 Unicode 与 Luhn 归一化**（ID-REVIEW-1017）— 形近字符与卡号校验位不再漏判。
- **🔐 OCR 识别出的文字也会参与敏感判定**（ID-REVIEW-1005）。
- **🔐 `sk-` 规则加上左边界**（ID-REVIEW-1025）— 以前 `task-`、`risk-`、`disk-` 这类普通词后面跟一串长字符也会被判成密钥，你的普通文字会在 24 小时后静默过期消失。
- **🔐 超大 RTF 内容落回纯文本分支**（ID-REVIEW-1004）——以前会被直接跳过。

**存储与后端**

- **⚙️ SQLite schema 版本权威化**（ID-REVIEW-1024）— 版本号写进数据库文件头并驱动迁移，迁移是原子的，数据库版本比构建新时拒绝打开（而非静默降级）。
- **⚙️ 回收站获得独立维度**（ID-REVIEW-1024）— 并把 v1→v2 的回收站映射钉死。
- **⚙️ 绑定值统一走 SQLiteBinder 并检查返回码**（ID-REVIEW-1024）——不支持的类型直接抛错，不静默写 NULL。
- **⚙️ 迁移前先读回校验**（ID-REVIEW-1024）。
- **⚙️ 标签保存不再误删条目↔标签的关联**（ID-REVIEW-1024）— 旧实现用一条 `DELETE FROM tags` 全量清表，级联把每一条历史记录的标签关联一起删光。**注意：这条修复在尚未启用的 SQLite 后端上，目前不作用于你的数据**（见上文「已就位，但尚未启用」）。
- **⚙️ 细粒度保存写真实标签而不是占位符**（ID-CRASH-0022）。
- **⚙️ 损坏 blob 的隔离路径改用注入的 defaults**（ID-REVIEW-1002），不再写到生产域。

### 其他 (Other)

- **⚡ 三个性能热点** — 剪贴板轮询不再每个 tick 都对整个 pasteboard 做指纹（ID-REVIEW-1024）；图片完整性扫描改为基于 mtime 缓存的增量扫描（ID-REVIEW-1019）；卡号检测正则预编译（ID-REVIEW-1020）。
- **🧪 测试稳定性** — 8 处固定 sleep 改为条件等待（ID-FLAKE-0001–0008）；图片渲染失败现在让测试失败而不是杀掉测试宿主（ID-TEST-1024）；同步保存回归测试不再写 `UserDefaults.standard`（ID-TEST-1024）；标签保存失败可被测（ID-CRASH-0065）；测试隔离统一到一条 seam，生产域永不被测试进程使用（ID-CRASH-0064 / ID-CRASH-0066）；ZZZ canary 重新启用（ID-REVIEW-1013）；CI 环境的 skip 从 46 处收敛到 7 处。
- **🚧 CI 门禁与工具链加固** — 所有 GitHub Actions 依赖全部 SHA pin（ID-REL-1）；tag 路径的测试门恢复（ID-REL-2）；每个 appcast 条目带上 Sparkle 的 `minimumSystemVersion` 与 `releaseNotesLink`（ID-REL-3 / ID-REVIEW-1021）；TSan 的 race 门禁改成真正 fail-closed，编译失败不再被误报成「0 个 race」（ID-CI-0022）；Sparkle 升到 2.10.0。
- **🧹 内部重构** — 10 个上帝对象（ClipboardStore / BackupPackage / AppDelegate / ItemListView / RestoreWizardViewModel / ImageStorage / CryptoService / HotKeyManager / FeedProbeEngine / ClipboardMonitor）的长函数按职责拆分；96 处 SwiftLint 机械告警清零并强制 LF 行尾。

## English

### Highlights

- **🗑️ A large Trash purge now asks you first** — When one purge would delete 20 or more expired entries, ClipMemory no longer acts on its own: the menu-bar icon lights up a red count badge, and clicking it opens the confirmation (Delete Forever / Cancel). Smaller purges stay silent. The retention window stops being a hard upper bound — data safety over retention semantics. (ID-CRASH-0035)
- **🛡️ The Trash and clipboard history no longer lose data silently** — a failed bin load is no longer overwritten with an empty array (which used to wipe your bin outright); deletions from the bin are visible instead of only reaching the log; and a failed clipboard write retries with an observable state. Two copies of ClipMemory running at once no longer overwrite each other either — the second process exits at launch without touching a byte. (ID-CRASH-0022 / 0032)
- **🛡️ A backup that missed quarantine copies now says so** — the failure used to take the WHOLE daily backup down with it (the backup directory was deleted); now it is recorded on its own channel, the backup itself completes as usual, and the reason is shown in red under Settings → Backup. The quarantined copies also travel with the daily backup and the export package (ID-BACKUP-0006), and a cross-volume Images/ hard link degrades to a copy instead of failing the whole daily backup (ID-REVIEW-1018).
- **🔐 `sk-` service tokens are recognised again** — vendor-prefixed keys (`sk-ant-…`, `sk-or-…`) have hyphens in the tail, so the previous rule stopped at the first one and missed them; they are detected now, without matching ordinary hyphenated words like `task-` or `risk-`. (ID-REVIEW-1024)
- **⚙️ A new SQLite storage layer is in place, but not yet switched on** — the real SQLite backend, the authoritative schema version, the atomic migration and the Trash's own dimension are all done (ID-REVIEW-1024, 23 commits — the largest body of work here). **Your data still lives in the same local file backend; neither the encryption format nor where data lives changed.** The new layer is a prepared component for a future cutover, and a few hard prerequisites remain before it can be wired up (see `docs/design/storage-migration.md` §4.4.1 / §5.5).

### Fixes

**Data safety**

- **🛡️ A purge now persists before it deletes image files** (ID-REVIEW-1024) — deleting first meant a crash left the two permanently out of step; the write now happens first and a failed write raises an alert.
- **🛡️ A refused quarantine restore no longer reports "the package is corrupted"** (ID-REVIEW-1024) — the package itself is intact; the refusal now gets its own wording.
- **🛡️ A momentarily unavailable keychain no longer reports "encryption failed, item not saved"** (ID-REVIEW-1024) — nothing was lost in that case (the key was never regenerated, nothing overwritten); the app now says it is retrying and that existing data is unaffected.
- **🛡️ A test process can no longer touch your real data** (ID-CRASH-0031) — the "is this production?" decision now uses the domain instead of instance identity, and the permanent-error retry loop and the isolation-path gaps are fixed in the same pass.
- **🛡️ The "already asked" marker for a large purge is now the set of entries, not the count** (ID-REVIEW-1025) — two purges of the same size used to look like the same batch, so the second one was silently skipped: the bin grew without bound and nothing said so.
- **🛡️ A batch you were asked about is no longer deleted automatically before you answer** (ID-REVIEW-1025) — restoring a few entries used to bring the rest below the threshold, and they were then purged as "routine housekeeping" without a decision. Asking now means asking.
- **🛡️ "Cancel" no longer locks the Quick Bar away** (ID-REVIEW-1025) — the badge used to stay up, so every later click on the menu bar icon opened the same confirmation and the Quick Bar could not be reached at all; only an app restart helped. Cancelling now defers the question: the badge goes, nothing is deleted, and the next cleanup tick asks again.
- **🛡️ The end of a pending purge is now announced** (ID-REVIEW-1025) — if you restored or deleted those entries yourself, the badge used to stay up and the Quick Bar stayed unreachable. The UI is told as soon as the state changes.
- **🛡️ Permanently deleting a bin entry no longer resurrects other entries** (ID-REVIEW-1025) — the in-memory state is now persisted before the delete, so a stale blob cannot overwrite it; a just-restored entry used to reappear in the bin (while also being in the history).

**Backup and restore**

- **⚙️ The export manifest's contract is now "the field is absent", not "the bytes are the same"** (ID-REVIEW-1024), and it counts the re-encrypted payload rather than the source.
- **⚙️ The v3 export seals its package key as one-shot** (ID-REVIEW-1015).
- **⚙️ The auto-backup error message is recorded before its date** (ID-REVIEW-1024) — the date in the log used not to match.
- **⚙️ Backups are hard-linked to each other, and the real disk usage is shown** (ID-REVIEW-1018) — the backup folder no longer looks N times larger than it is.
- **⚙️ The red warning no longer sticks around after the quarantined copies are recovered** (ID-REVIEW-1025) — the old record never cleared itself, and its denominator overstated how many copies were missing.

**Sensitive-content detection**

- **🔐 Unicode and Luhn normalization** (ID-REVIEW-1017) — look-alike characters and card check digits no longer slip through.
- **🔐 OCR-extracted text now takes part in sensitive detection** (ID-REVIEW-1005).
- **🔐 Oversized RTF falls through to the plaintext branch** (ID-REVIEW-1004) instead of being skipped.
- **🔐 The `sk-` rules now require a left boundary** (ID-REVIEW-1025) — an ordinary word like `task-`, `risk-` or `disk-` followed by a long run of characters used to be flagged as a key, so your own text silently expired out of the history after 24 hours.

**Storage and backends**

- **⚙️ The SQLite schema version is authoritative** (ID-REVIEW-1024) — it lives in the database file header and drives the migration, the migration is atomic, and a database newer than this build is refused rather than silently downgraded.
- **⚙️ The Trash gets its own dimension** (ID-REVIEW-1024), with the v1→v2 bin mapping pinned down.
- **⚙️ Bound values all go through the binder, and the result codes are checked** (ID-REVIEW-1024) — an unsupported type throws instead of silently writing NULL.
- **⚙️ The migration is read back and verified before it is accepted** (ID-REVIEW-1024).
- **⚙️ Saving tags no longer wipes the item↔tag links** (ID-REVIEW-1024) — the old code issued a blanket `DELETE FROM tags`, whose cascade took every history entry's tag link with it. **Note: this fix lands in the not-yet-enabled SQLite backend and does not touch your data today** (see the "in place, but not yet switched on" highlight above).
- **⚙️ The granular save writes the real tag, not a placeholder** (ID-CRASH-0022).
- **⚙️ The corrupt-blob quarantine path uses injected defaults** (ID-REVIEW-1002) instead of writing to the production domain.

### Other

- **⚡ Three performance hot spots** — the clipboard poll no longer fingerprints the whole pasteboard on every tick (ID-REVIEW-1024); the image integrity scan is incremental via an mtime cache (ID-REVIEW-1019); card-detection regexes are precompiled (ID-REVIEW-1020).
- **🧪 Test stability** — 8 fixed sleeps became condition waits (ID-FLAKE-0001–0008); a failed image render now fails the test instead of killing the test host (ID-TEST-1024); the sync-save regression tests no longer write `UserDefaults.standard` (ID-TEST-1024); a failed tag save is testable (ID-CRASH-0065); test isolation is unified onto one seam that never uses the production domain (ID-CRASH-0064 / ID-CRASH-0066); the ZZZ canary is re-enabled (ID-REVIEW-1013); CI-environment skips narrowed from 46 to 7.
- **🚧 CI gates and tooling hardened** — every GitHub Actions dependency is SHA-pinned (ID-REL-1); the tag-path test gate restored (ID-REL-2); every appcast item carries Sparkle's `minimumSystemVersion` and `releaseNotesLink` (ID-REL-3 / ID-REVIEW-1021); and the TSan race gate is now genuinely fail-closed, so a compile failure is no longer reported as "0 races" (ID-CI-0022); Sparkle moves to 2.10.0.
- **🧹 Internal refactoring** — long functions in 10 god objects (ClipboardStore / BackupPackage / AppDelegate / ItemListView / RestoreWizardViewModel / ImageStorage / CryptoService / HotKeyManager / FeedProbeEngine / ClipboardMonitor) were split by responsibility; 96 mechanical SwiftLint warnings cleared and LF line endings enforced.

### Upgrade Note

- Versions with the auto-update module (Sparkle, v2.4.0+): wait for in-app auto-update, or run `brew upgrade --cask clipmemory`
- This release changes the semantics of the Trash's retention window: it no longer guarantees deletion on expiry. Keep your existing setting — large purges will ask you first
- Your data is still encrypted locally with the key still in the Keychain; neither where data lives nor the encryption format changed
