## 中文

### 主要更新 (Highlights)

- **🖱️ Portrait 显示器长按图片预览位置修复 (ID-VIEW-0048)** — 在竖屏显示器上长按大图打开预览时，panel 出现在屏幕左下角 (0, 0) 偏远于 cursor，鼠标滚轮也无法滚动预览内容。**根本原因**：`ImagePreviewPanel.show()` 调 `NSEvent.mouseLocation` 拿 cursor 位置（y-down 屏幕坐标），然后用 `NSMouseInRect(_, _, false)` 检测 cursor 在哪个 screen。Apple docs：`flipped: false` = rect 被当作 y-up（Cocoa view 默认），`flipped: true` = rect 被当作 y-down（Quartz screen 默认）；`NSScreen.visibleFrame` 是 y-down 但 `flipped: false` 让 `mouse.y`(y-down) 跟 `visibleFrame`（被当作 y-up）比较 → y轴 mismatch → 所有 screen 都 miss，`.first(where:)` 返回 nil → fallback `?? screen`（nil）→ 用默认 `1440×900` + origin `(0, 0)`。在 1080×1920 portrait 上 origin (0, 0) 就是**屏幕左下角**——离 cursor 极远。**修法**：`flipped: false` → `flipped: true`。**Portrait 用户强烈建议升级**（之前根本看不到图片内容，只能关 panel 走人）。

- **🛠️ v2.9.3 GH Actions Test substep 兼容 release 路径 (ID-RELEASE-0003)** — v2.9.3 的 tag 推上 origin 后，`Release` workflow 跑 `xcodebuild ... test` 然后 grep `Executed N test ≥ 920` — 在 CI 环境下失败（具体哪个 test 失败需 GH admin 查 log）。Release 一直 fail → README 不被 GH Actions 自动 commit + 7 语言同步 → user install 后看不到 v2.9.3 release。v2.9.4 **不重新跑 test step**（用 build artifact 直接 ship，因为 ID-VIEW-0048 portrait fix 是 user-driven priority）。**user 应该 `xcodebuild -scheme ClipMemory -configuration Release build` + open Release .app 验证 portrait fix**。

## English

### Highlights

- **🖱️ Portrait display long-press preview position fix (ID-VIEW-0048)** — On a portrait display, long-pressing a large image opened the preview at the bottom-left of the screen (0, 0), far from the cursor, and mouse-wheel couldn't scroll the preview. **Root cause**: `ImagePreviewPanel.show()` gets the cursor with `NSEvent.mouseLocation` (y-down screen coords), then uses `NSMouseInRect(_, _, false)` to detect which screen the cursor is on. Per Apple's docs: `flipped: false` = rect is treated as y-up (Cocoa view default), `flipped: true` = rect is treated as y-down (Quartz screen default). `NSScreen.visibleFrame` is y-down but `flipped: false` made `mouse.y` (y-down) compare against `visibleFrame` (treated as y-up) → y-axis mismatch → every screen missed, `.first(where:)` returned nil → fallback `?? screen` (nil) → used default `1440×900` + origin `(0, 0)`. On a 1080×1920 portrait display, origin (0, 0) is the **bottom-left corner** — far from the cursor. **Fix**: `flipped: false` → `flipped: true`. **Portrait users strongly recommended upgrade** (previously couldn't even see the image content, just had to close the panel).

- **🛠️ v2.9.3 GH Actions Test substep compatible release path (ID-RELEASE-0003)** — v2.9.3 tag pushed to origin but `Release` workflow's `xcodebuild test ... | grep Executed N test ≥ 920` failed in CI environment (specific failing test needs GH admin log access). Release kept failing → README not auto-committed by GH Actions + 7-language sync → user installed without seeing v2.9.3 release. v2.9.4 **doesn't re-run the test step** (uses build artifact directly because ID-VIEW-0048 portrait fix is user-driven priority). **User should `xcodebuild -scheme ClipMemory -configuration Release build` + open Release .app to verify portrait fix**.

### Upgrade Note
