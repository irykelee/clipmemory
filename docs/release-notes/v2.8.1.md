## English

### Highlights

- **🛡 Fix silent clipboard data loss on disk-full / permission-denied (ID-SILENT-0021, HIGH)** — `ClipboardStore.flushSave()` now wraps `saveItems()` in `do/catch`; on failure it restores `needsSave = true` for the next timer-fire retry and posts a new `.clipboardSaveFailed` notification. Previously, when `backend.saveBlob` threw (disk full / permission denied / iCloud Drive sync conflict) and the user had no subsequent mutation to trigger `saveImmediately` retry, the in-memory items would never reach disk for the rest of the session — and clipboard data is not user-recreatable. The real-loss condition is narrow (disk error persists ≥ 500ms + no subsequent mutation + user quits) but real. New `Notification.Name.clipboardSaveFailed` provides a UI surface channel for future diagnostics banners.

### Other

- **🛠 Fix session-lifetime blank rows after key re-ready (ID-SILENT-0019, MEDIUM)** — `handleCryptoKeyPrepared(success:)` now also resets `items[].decryptionFailed = false` for all items, in addition to the v2.8.0 `pendingFailedIDs.removeAll()`. Previously `mergePendingDecryptionFailures` set the flag permanently; even after the user received the key-ready notification, the items stayed blank until app restart. Together with v2.8.0 (ID-STORE-0010), this completes the symmetric fix: negative cache clear + pendingFailedIDs clear + decryptionFailed flag reset = cold-start key-not-ready data loss fully closed.

- **🛠 Fix release-config XCTest isolation bypass (ID-SYNC-0006, MEDIUM)** — `NoOpFeedProbeEngine` class and the `if isRunningTests` guard in `_sharedDefault` are no longer wrapped in `#if DEBUG`. XCTest sets `XCTestConfigurationFilePath` regardless of build configuration, so release-config XCTest runs would otherwise bypass the guard (compiled out), trigger a real `SPUStandardUpdaterController` startup + real appcast HTTP probe, and re-open the NEW-3 pollution path. The class is safe in release builds (`@unchecked Sendable`, no mutable state, only referenced when `isRunningTests` is true at the call site).

- **🛠 7 LOW doc/log tightening (MISC-0008/0009/0013 + SHELL-0001/0002 + SECURITY-0008 + SILENT-0022)**
  - `Scripts/release.sh:597` — inline WHY comment on the NEW-8 `grep -c` fix explaining the 0-match exit-1 + newline quirk that the fix neutralizes
  - `UpdateFeedPolicy.swift` — stale line references corrected from `:103/127` to `:112/136` (diff-hunk line number trap recurrence)
  - `ZZZSuiteTeardownTests.testSuiteTeardownMarker` — empty body now has `XCTAssertTrue(true)` + comment explaining XCTest class-discovery marker intent
  - `Scripts/sync_gitee_release.sh:196` — `--max-time 600` (was 180) comment explains the 3.3x increase for slow-network uploads; `2>/tmp/upload.err` comment explains why the outlier idiom (vs `2>&1`) is security-critical — needs the file as buffer for the access-token redaction grep
  - `CryptoService.constantTimeCompare` — doc comment explaining the length-mismatch early-return leak is theoretical (only HMAC-SHA256 verification, fixed 32-byte tag)
  - `CryptoService.decryptLegacy` — HMAC mismatch now logs an explicit `HMAC mismatch` error, bringing the legacy path to parity with `decryptV2`'s authentication-failure distinction

- **🛠 7 XCTest notification tests switched to observer-driven waits (ID-TEST-0001)** — `CryptoKeyPreparedNotificationTests` + `ClipboardStoreDecryptionFlagResetTests` (7 cases total) replace the `DispatchQueue.main.asyncAfter(deadline: .now() + 0.1) { exp.fulfill() }` 100ms time-based wait with `NotificationCenter.addObserver(forName:object:queue:.main) { exp.fulfill() }` + `defer { removeObserver }`. CI load can make 100ms windows flaky; idle machines waste 100ms. Observer registers synchronously, so `wait` returns the moment the observer fires (typically <1ms).

### Upgrade Note

- Sparkle auto-update (v2.4.0+) handles the upgrade automatically, or `brew upgrade --cask clipmemory`
- This is a pure patch release: no breaking change, no API change, no data migration; existing v2.8.0 users upgrade with zero-visible-change
- ID-SILENT-0021 fixes a narrow trigger (disk full + no subsequent mutation + user quits) — most users never hit it; the fix has no observable side-effects on normal operation
