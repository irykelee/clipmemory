### 主要更新 (Highlights)

- **🆕 回收站批量恢复（NEW-batch-restore）** — Trash tab 现在支持多选 + 一键恢复：行内 checkbox + 顶部 master checkbox（全选/全不选/部分选中三态）+ Shift+点击选区 + Restore 按钮根据选中数动态显示「Restore N items」。「一条一条点」历史结束。配合已有永久删除按钮，回收站工作流从「不可用」升级到「真工具」。

## English

### Highlights

- **🆕 Trash batch restore (NEW-batch-restore)** — Trash tab now supports multi-select + one-click restore: per-row checkbox + top master checkbox (tri-state all/none/mixed) + Shift+click range select + Restore button that dynamically shows "Restore N items". The "one click at a time" history is over. Together with the existing permanent-delete button, the trash workflow upgrades from "unusable" to "real tool".
- **🛡 Fix dev-build polluting production UserDefaults causing silent clipboard data loss (ID-STORE-0014, CRITICAL)** — `ClipboardStore.swift:129` `maxItems` didSet previously wrote to `UserDefaults.standard` instead of the injected defaults suite; XCTest runs (e.g. `M-2 testXxx.maxItems = 3`) would silently set the user's production `com.clipmemory.app` cap to 3, and old entries would be trimmed on next launch. Fix uses `xcTestDefaults` static seam + XCTestObservation per-test cleanup + 4 sibling didSets + 4 init reads all switched to the injected defaults suite. **This is the root-level fix for the user's "future dev versions must not affect production app use" requirement**.

### Other

- **🛠 Import overflow routes through trash (M-2)** — `importBackupItems` now detects post-import item count exceeding maxItems and routes overflow through `moveToTrash` (recoverable) instead of dropping. `itemsExceedingMaxItems()` helper extracts the trim logic as single source of truth, preserves the C-1 pinned-not-trimmed exemption. Image-import failure auto-fallback alert (NEW-3).

- **🛠 7 audit-driven "use Apple defaults" refactors (PR #40-#47, docs/superpowers/audits/2026-08-10-apple-api-reuse-audit.md)**:
  - PR #40 `SelectCheckbox` + `CloseButton` shared component extraction — eliminates size drift (sz 10/11/14/16) across 5 ad-hoc checkbox/X-button usages
  - PR #41 `NSWindow.setFrameAutosaveName` replaces hand-rolled JSON window persistence — drops 50+ lines of JSON + debounce + off-screen check
  - PR #42 `Notification.Name` unified registry gap-fill — 2 bare strings join the existing registry, the `NotificationObserverAssertionTests` regression gate now covers them
  - PR #43 4 bare keyCodes (126/125/36/53/3) → Carbon `kVK_*` constants
  - PR #44 search debounce 250ms/150ms unified to 250ms
  - PR #45 `sz()` clamp `<4` rationale comment (vs Settings 3 steps)
  - PR #46 `sz()` boundary test pinning (3 steps + 4.0/3.999 + scale=0)
  - PR #47 L24 sweep after PR #40 migrates 2 remaining usages + fixes 1 hardcoded font size

### Upgrade Note

- Sparkle auto-update (v2.4.0+) handles the upgrade automatically, or `brew upgrade --cask clipmemory`
- Pure minor release: no breaking change, no API change, no data migration; existing v2.8.1 users upgrade with zero-visible-change
- ID-STORE-0014 fix is invisible — your maxItems setting is preserved, dev versions just no longer pollute production data
- PR #41 NSWindow autosave takes over frame persistence: **window position resets once on first v2.8.2 launch** (the old `WindowFrame` key is no longer read); user-dragged/resized position is preserved from the second launch onward
