# 剪忆 ClipMemory v2.7.0 — F-1 @MainActor migration / F-1 @MainActor 迁移完成

**发布日期 / Release Date**: 2026-07-28
**类型 / Type**: Minor release (refactor-only + 1 user-facing fix)

## 中文

### 主要更新 (Highlights)

- **启动时语言 picker 与 UI 文案一致性修复** — 之前如果保存的是非英语语言，启动后 Settings 窗口内的 UI 文案仍然是英文（Language picker 显示正确）。v2.7.0 修复后，启动即生效。
- **核心类全面 Swift 并发兼容** — `LanguageManager` / `TrashStore` / `ClipboardStore` 三个核心类加 `@MainActor`，由类型系统保护 main-thread contract，避免未来回归。
- **657 个测试全过，0 失败** — 内部架构加固无功能回归。

### 修复 (Fixes)

- **启动时非英语语言 UI 文案仍显示英文** — Swift `didSet` 在 `init()` 内不触发，新增的 `currentLanguageCode` 镜像需显式 seed 才能从启动时刻起可用。

### 重构 (Refactors)

- **`LanguageManager` 改用 `nonisolated` 镜像** — `L10n.string()` 等 off-main reader（来自 `CryptoService.prepareKey` failure handler 等 `Task.detached`）读语言代码不再跨 main-actor 边界。
- **`LanguageManager` 加 `@MainActor`** — 让 `selectedLanguage.didSet` 的 `Thread.isMainThread` + `DispatchQueue.main.async` defensive 兜底被类型系统证明 unreachable。
- **`TrashStore` 加 `@MainActor`** — 让 `@Published var trashedItems` 等 state 由类型系统保护（之前是 implicit「callers must ensure main thread」contract）。`deinit` 改用 `NSApplication.willTerminateNotification` observer，`flushPendingSaves` 行为不变。
- **`ClipboardStore` 改用类级 `@MainActor`** — 删除 phase 2 临时加在 `ClipboardStore` 的 ~26 个 per-method `@MainActor` 标注，由 class-level `@MainActor\nfinal class ClipboardStore` 作为 single source of truth。
- **3 个 internal refactor 用 Swift Concurrency primitives** — cleanup timer 三跳 → 单个 `Task { @MainActor in ... }`；deinit via willTerminate observer（镜像 phase 2 TrashStore pattern）；OCR backfill sync/async hybrid（保留 sync main-thread path 给 common case，Task async 给 bg-thread callers）。
- **6 个 caller adaptation 因 class-level isolation tightening** — TagPickerLogic/NewTagLogic static func、AppDelegate.setupClipboardMonitor、AppDelegate inline closures 加 `@MainActor`；AppDelegate `parseExcludedBundleIds()` + BackupPackage.swift:529 `importBackupTags` wrap `MainActor.assumeIsolated`；HistoryCaptureSettingsViewTests 加 `@MainActor`。

### 升级提示 (Upgrade Note)

- v2.4.0 起带自动升级模块（Sparkle）的版本：等 App 内自动更新，或 `brew upgrade --cask clipmemory`
- 这是 refactor release，**用户使用方式不变**。所有 clipboard 数据、设置、标签、回收站、备份、OCR 索引、加密密钥均保留。

## English

### Highlights

- **Startup language picker / UI strings consistency fix** — When saved language was non-English, the Settings window UI rendered English strings even though the Language picker showed the correct selection. v2.7.0 fixes this; the saved language takes effect from app launch.
- **Core classes fully Swift Concurrency-compatible** — `LanguageManager`, `TrashStore`, and `ClipboardStore` now carry class-level `@MainActor`, enforcing the main-thread contract at the type-system level and preventing future regressions.
- **657 tests passing, 0 failures** — internal architectural hardening with no functional regression.

### Fixes

- **Settings window UI rendered English when saved language was non-English** — Swift `didSet` observers don't fire during `init`; the new nonisolated language code mirror needed to be seeded explicitly to be usable from app launch.

### Refactors

- **`LanguageManager` switched to `nonisolated` mirror** — Off-main readers of the language code (e.g. `L10n.string()` invoked from `CryptoService.prepareKey` failure handlers running in `Task.detached`) no longer cross the main-actor boundary.
- **`LanguageManager` got `@MainActor`** — The `Thread.isMainThread` + `DispatchQueue.main.async` defensive fallback in `selectedLanguage.didSet` is now provably unreachable at the type level.
- **`TrashStore` got `@MainActor`** — `@Published var trashedItems` and other state mutations are type-system-protected (previously implicit "callers must ensure main thread" contract). `deinit` switched to `NSApplication.willTerminateNotification` observer; `flushPendingSaves` behavior unchanged.
- **`ClipboardStore` switched to class-level `@MainActor`** — Removed the ~26 per-method `@MainActor` annotations added in phase 2; class-level `@MainActor\nfinal class ClipboardStore` is the single source of truth.
- **Three internal refactors replaced workarounds with Swift Concurrency primitives** — cleanup timer collapsed triple-hop into a single `Task { @MainActor in ... }`; deinit moved to a `willTerminateNotification` observer (mirrors phase 2 TrashStore pattern); OCR backfill uses a sync/async hybrid (sync when caller is already on main thread, `Task { @MainActor }` otherwise).
- **Six caller adaptations for class-level isolation tightening** — `@MainActor` added to TagPickerLogic / NewTagLogic static funcs, AppDelegate.setupClipboardMonitor, AppDelegate inline closures; `MainActor.assumeIsolated` wraps on AppDelegate's `parseExcludedBundleIds()` call and `BackupPackage.swift:529 importBackupTags`; `@MainActor` added to HistoryCaptureSettingsViewTests.

### Upgrade Note

- Versions with the auto-update module (Sparkle, v2.4.0+): wait for in-app auto-update, or run `brew upgrade --cask clipmemory`
- This is a refactor release — **no user-facing behavior change**. All clipboard data, settings, tags, trash, backups, OCR index, and encryption keys are preserved.
