# 剪忆 ClipMemory v2.7.2 — Fuzzy Search & Image Integrity + Cryptographic Safety / 模糊搜索与图片完整性扫描 + 密码安全加固

> **关系 / Relation to v2.7.1**: v2.7.1 was YANKED 2026-07-29 (release title claimed Search Performance but the related work was not in the tag). v2.7.2 is the corrected release with the actual content matches its title. v2.7.1 users will be auto-updated to v2.7.2 via Sparkle.

**发布日期 / Release Date**: 2026-07-29
**类型 / Type**: Patch release (yanked-v2.7.1 replacement)
**替代 / Supersedes**: v2.7.1 (yanked)

## 中文

### 主要更新 (Highlights)

- **🔍 拼音感知模糊搜索** — 「zhongwen」也能匹配「中文文档」；空格分隔的多个词必须全部命中（token AND matching）；同时忽略大小写和音调符号
- **🖼️ 启动时图片完整性扫描** — App 启动后异步扫描所有图片条目，标记缺失/损坏文件，列表项立即显示状态（无需等待每次点击）
- **🔑 解密失败诊断** — Keychain 锁定时搜索页显示黄色诊断横幅说明原因，不再静默空结果
- **⚡ 缓存预热** — 主线程不再同步解密；预热覆盖 App 唤醒、新条目捕获、列表首次显示

### 修复 (Fixes)

- **Keychain 临时锁定不再永久标记条目** — 修了一个潜伏 bug：Keychain 瞬态锁定后条目曾被永久标记为「不可解密」，现在 key 恢复后可自动重试
- **DI 容器安全性** — `ServiceContainer.crypto` 改为 `private(set)`
- **AES-CBC 实现合并** — 删除 ImageStorage 中重复的 CBC 解密实现
- **Swift 严格并发** — 启用 `-strict-concurrency=minimal`
- **图片去重优化** — 同图多次复制不再产生重复文件

### 升级提示 (Upgrade Note)

- v2.7.1 已撤回。如果你的 App 是 v2.7.1，Sparkle 自动推送本次更新
- v2.7.0 或之前版本：等 App 内自动更新，或 `brew upgrade --cask clipmemory`
- 首次启动时图片完整性扫描会异步运行（不阻塞 App 启动），列表中标记为 ⚠️ 的图片可在 Trash 中查看详情

## English

### Highlights

- **🔍 Pinyin-aware fuzzy search** — "zhongwen" matches "中文文档"; space-separated tokens must all match (token AND matching); case-insensitive and diacritic-insensitive
- **🖼️ Startup image integrity scan** — Async scan on app launch marks missing/corrupted image files; list items display status immediately without per-click disk I/O
- **🔑 Decryption failure diagnostics** — Yellow banner explains why search results are empty when Keychain is locked, replacing silent empty results
- **⚡ Cache prewarming** — Decrypts no longer block main thread; prewarming covers app wake, new item capture, and list first-display

### Fixes

- **Transient Keychain lock no longer permanently marks items** — Fixed latent bug where items were permanently labeled "undecryptable" after a transient Keychain lock
- **DI container hardening** — `ServiceContainer.crypto` now `private(set)`
- **AES-CBC implementation deduplication** — Removed duplicate CBC decrypt in ImageStorage
- **Swift strict concurrency** — Enabled `-strict-concurrency=minimal`
- **Image dedup optimization** — Repeated copies of the same image no longer create duplicate files

### Upgrade Note

- v2.7.1 was yanked; existing v2.7.1 users will receive this update via Sparkle
- v2.7.0 or earlier: wait for in-app auto-update, or `brew upgrade --cask clipmemory`
- First launch will async-scan image integrity (non-blocking); items marked ⚠️ can be inspected in Trash

## 安装 / Install

```bash
# Homebrew Cask
brew tap irykelee/clipmemory
brew trust irykelee/clipmemory
brew install --cask clipmemory

# Manual download
# https://github.com/irykelee/clipmemory/releases/download/v2.7.2/ClipMemory.tar.gz
```

> **首次打开若提示「Apple 无法验证…」/ If macOS blocks the first launch with "Apple cannot verify…"**：这是 macOS 对未公证应用的常规拦截，不是病毒。右键点 App →「打开」→ 再点「打开」；或 系统设置 → 隐私与安全性 →「仍要打开」。仅需操作一次。/ This is the standard prompt for non-notarized apps, not malware. Right-click the app → **Open** → **Open** again; or System Settings → Privacy & Security → **Open Anyway**. Only needed once.
