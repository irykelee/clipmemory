# 剪忆 ClipMemory v2.9.1 — 静默失败修复与签名边界说明 / Silent Failure Fixes & Signing Boundary

**类型 / Type**: Patch release（5 项静默失败修复 + 1 项签名边界文档化 + 1 项 pbxproj 工程文件回填；10 commits since v2.9.0）

**发布日期 / Release Date**: 2026-08-15

## 中文

### 主要更新 (Highlights)

- **🔧 备份还原静默失败修复 (ID-STORE-0012 M-3)** — `importBackupItems` 此前会把回收站里同 hash 的条目算进 dedup set，结果：**回收站里仍有同 hash 条目时，备份还原会"成功"但实际什么都没导入**；等 30 天回收站过期后，原数据彻底丢失。修法：dedup set 只看 items，不再看 trashed items。回归测试覆盖 3 种相邻不变量（核心 RED→GREEN + ID dedup + 包级 hash 冲突）。**这是真实数据丢失修复，强烈建议升级**。

- **🔧 测试隔离解锁 (ID-STORE-0015 C-1)** — `FileStorageBackend` 此前硬连 `UserDefaults.standard`，导致 TrashStore 的回收站加载失败路径无法在不污染生产 keys 的前提下测。修法：init 加 `defaults: UserDefaults = .standard` seam，5 处 `.standard` 改 `defaults`。**用户行为不变**（默认仍是 `.standard`），但未来 multi-suite 隔离 + TrashStore 真路径测试解锁。架构级改动，无 breaking change。

- **🔧 Sparkle 更新源空 body 修复 (ID-UPDATE-0004 F-1 + F-2)** — `FeedProbeEngine.fetchBody` 此前对 200 + 0 字节响应返回 `""`（空字符串），上游视为"feed reachable" → Sparkle 收到 zero-item appcast → 显示「已是最新」，**但实际上 appcast 已被 CDN 清空，新版本永远收不到**。修法：空 body 与非 UTF-8 body 同等处理（return nil + logger.error），上游走 `.bothDownKeepPrimary` 决策分支（保留主 URL，UI 显示「主备都不可达」）。**这是真 silent failure 修复，强烈建议升级**。

- **🔧 备份清理失败修复 (ID-STORE-0016 E-1)** — `pruneOldBackups` 此前对 `contentsOfDirectory` 失败 silently return（perms 撤销 / 父目录被删 / 沙盒拒绝 → Backups/ 单调增长）。修法：失败时记录 `lastPruneErrorDate` + `lastPruneErrorMessage` UserDefaults pair + 设置页 footer 加红色提示行 + 7 语种 L10n。**保留 primary URL，UI 显式报"清理已停"**。

- **🔧 备份日期 corruption 警告 (ID-STORE-0017 E-2)** — `lastBackupDateKey` 若被存成非 Date 类型（程序误用 `defaults.set(Int, ...)` / 损坏迁移），`as? Date` 静默返回 nil → throttle 跳过 → 备份每次启动都跑。修法：fail-open 行为保留（更多备份 = 更安全），仅加 `logger.warning` 提示 corruption 类型 + 行为（operator via Console.app 可见）。**用户面板表面留未来**（可复用 ID-STORE-0016 的 settings footer 模式）。

- **📜 签名与分发边界说明 (ID-DOCS-0003)** — 7 语种 README 加 `### 签名与分发说明` 段，明确告知：当前是 **Personal Team 签名**（ad-hoc, 无 notarization），适合开发者本机 + `brew install` 用户；企业 MDM / Mac App Store / 严格零接触自动更新场景需 fork + 自费 $99/年注册 Apple Developer Program + 改 `project.yml` + release.yml 加 3 步 notarization。**这是 2026-07-19 commit `307818e` 已锁定的决策**（详见 STATUS.md），不改代码，只文档化分发边界。

- ID-DOCS-0003 不动代码，只是首次从 GitHub Releases 手动下载的用户看到 macOS Gatekeeper 提示时的解释文档化（"这是 Personal Team 签名的常规拦截，不是病毒"）

## English

### Highlights

- **🔧 Backup restore silent failure fix (ID-STORE-0012 M-3)** — `importBackupItems` previously included the trash list in the hash dedup set, so a backup restore that succeeded but actually imported nothing whenever a matching-hash entry sat in the trash; after the 30-day retention window expired, the original data was gone for good. Fix: dedup set now only scans live items, not trashed items. 3 regression tests cover the core RED→GREEN + ID dedup + package-level hash collision. **This is a real data-loss fix — upgrade strongly recommended.**

- **🔧 Test isolation unblocked (ID-STORE-0015 C-1)** — `FileStorageBackend` was hardcoded to `UserDefaults.standard`, so the TrashStore's recovery-from-corrupt-blob path couldn't be exercised under XCTest without polluting production keys. Fix: init now accepts `defaults: UserDefaults = .standard`, five `.standard` references switched to `defaults`. **User-visible behavior is unchanged** (default is still `.standard`), but future multi-suite isolation work and TrashStore real-path testing are unblocked. Architectural change, no breaking change.

- **🔧 Sparkle feed empty-body fix (ID-UPDATE-0004 F-1 + F-2)** — `FeedProbeEngine.fetchBody` previously returned `""` (empty string) for a 200 + 0-byte response; upstream treated that as "feed reachable" → Sparkle received a zero-item appcast → showed "you're up to date", **but the CDN had actually emptied the appcast and a new version would never be picked up**. Fix: empty body is now treated the same as non-UTF-8 (return nil + logger.error); upstream falls back to `.bothDownKeepPrimary` (primary URL retained, UI shows "both feeds unreachable"). **Real silent failure fix — upgrade strongly recommended.**

- **🔧 Backup prune failure surfaced (ID-STORE-0016 E-1)** — `pruneOldBackups` previously silently returned on `contentsOfDirectory` failure (perms revoked / parent deleted / sandbox denied → Backups/ grew unbounded). Fix: failure now records `lastPruneErrorDate` + `lastPruneErrorMessage` UserDefaults pair + Settings footer adds a red status row + 7-language L10n key. **Primary URL retained; UI explicitly reports "cleanup has stopped".**

- **🔧 Backup date corruption warning (ID-STORE-0017 E-2)** — If `lastBackupDateKey` was ever written as a non-Date value (programmer `defaults.set(Int, ...)` by mistake / broken migration), `as? Date` silently returned nil → throttle skipped → backup ran every launch. Fix: fail-open behavior preserved (more backups = safer), only adds `logger.warning` with the corruption type and behavior (operator-visible via Console.app). **User-panel surface deferred** — the same settings-footer pattern from ID-STORE-0016 can be reused when the next major version needs it.

- **📜 Signing & distribution boundary documented (ID-DOCS-0003)** — 7-language READMEs now ship an explicit "### Signing & Distribution" section: current signing is **Personal Team** (ad-hoc, no notarization), suitable for developer machines + `brew install` users; enterprise MDM / Mac App Store / strict zero-touch auto-update requires forking + paying $99/year for Apple Developer Program + changing `project.yml` + adding the 3 notarization steps to release.yml. **This is the locked decision from 2026-07-19 commit `307818e`** (see STATUS.md), no code change — just documents the distribution boundary.

### Upgrade Note

- Patch release, **no data migration / no breaking change**; v2.9.0 users auto-upgrade, history and settings preserved
- M-3 fix is invisible to 99% of users (your data wasn't lost), but anyone who has previously run an import while the trash happened to hold a same-hash entry may have experienced "import succeeded but nothing appeared"; re-importing after this upgrade recovers the data
- ID-DOCS-0003 doesn't change code, it just explains the macOS Gatekeeper prompt that first-time manual-download users see ("Personal Team signing — not malware, here's the workaround")
- 884/884 tests GREEN + ZZZ canary 3/3
- One Xcode project file catch-up (`project.pbxproj` adds PBXBuildFile entries for today's L26 test files so CI doesn't skip them)
