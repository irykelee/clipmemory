## Background

v2.9.3 release (`149906d`) included a `Run tests` substep failure on
GH Actions that was never identified per-test. v2.9.3 binary was
never published as a result. v2.9.4 (`a1cd997`) shipped with a
`|| true` workaround (which accidentally fail-opened by tee + shell
default behavior, not by the `|| true` clause), then `da3cc6a`
reverted the workaround. The `ID-CI-0011` linter now blocks any new
`|| true` on the Run tests step.

## Confirmed
- Local `xcodebuild test -configuration Debug` at HEAD `d265f71`:
  1019/1019 GREEN in ~50s. The failure is CI-environment-specific.

## Open hypotheses (in priority order)
1. GH Actions runner flake pattern (see `feedback/gh-actions-runner-flake-2026-09-24.md`)
2. `SyncBarrier` 5s timeout too tight on CI runner load
3. Genuine test ordering issue under CI parallelism

## Reproduce instructions (for future debugging)
```
git checkout 149906d  # v2.9.3
xcodebuild test -only-testing:ClipMemoryTests/IntegrationTests \
                 -only-testing:ClipMemoryTests/ConcurrencyTests \
                 -destination 'platform=macOS' 2>&1 | tee xctest.log
```
The failure surface (if any) should appear in `xctest.log` near a
SyncBarrier / backend.appData read. Compare against the local-run
baseline at HEAD `d265f71` (1019/1019 GREEN).
